# 极简出行穿搭三页改造设计

日期：2026-09-20

## 目标

在现有“每日穿搭”Taro 4 + React 18 项目上重构首页、信息采集/计算页和结果页。保留现有城市选择、Cloudflare Worker 天气服务、Coze workflow 和约 90 秒真实生成流程，不重做项目，不提前实现亲子、账号、历史记录、商城等后续功能。

## 本期范围

### 包含

- 极简首页与单一主入口。
- 四项信息采集：目的地、日期、穿衣风格、喜好颜色。
- 风格和颜色多选。
- 保留现有真实天气与 workflow 调用。
- 重绘约 90 秒 AI 计算页。
- 结果页天气概览、穿搭策略、整套图片和搭配清单。
- 下载结果图片与重新设计。
- 移除底部 TabBar 及旧功能入口。
- 移动端优先的莫兰迪自然有机视觉系统。

### 不包含

- 登录、注册、用户中心。
- 我的穿搭、收藏、分享。
- 历史方案列表和 LocalStorage 方案记录。
- 积分、商城、亲子功能。
- 修改 Coze 工作流拓扑或批处理逻辑。
- 额外调用图片模型生成独立单品图片。

## 技术策略

保留现有 Taro 4 + React 18 架构，通过 npm 引入 TailwindCSS 3 和 Framer Motion。Tailwind 用于三页的新布局和视觉原子类；Framer Motion 仅用于 H5 页面容器和装饰层的淡入、漂浮、缓动，业务状态、Taro 路由和服务层保持不变。现有 Sass 模块可继续承载 Taro 特有样式，避免为了工具迁移重写稳定组件。

旧页面源码保留，便于未来恢复或迁移，但从 `app.config.ts` 移除 `tabBar`，新流程不再暴露“我的”“我的穿搭”等入口。

## 页面结构

### 首页

首页为单屏沉浸式入口：

- 主标题固定为“你的专属出行穿搭助手”。
- 超大主按钮为“开始设计我的出行穿搭”。
- 右上角低对比度显示“历史方案”，本期点击不执行导航或提示。
- 不显示定位、轮播、天气、最近方案或其他快捷入口。
- 背景使用米白和鼠尾草绿的低饱和渐变光斑，装饰元素缓慢漂浮。

主按钮进入现有 `/pages/plan/index`。

### 信息采集页

信息采集页只显示四组输入，全部以点击选择为主：

1. 目的地：进入现有城市选择页，支持国内外搜索联想；确认后返回并回显完整城市。
2. 日期：选择开始和结束日期，支持当天至未来 7 天内、最多 7 个日历日。
3. 穿衣风格：多选“休闲度假、商务出差、运动户外、拍照出片”，选中态使用柔和实色背景和轻微缩放反馈。
4. 喜好颜色：多选“燕麦白、雾霾蓝、鼠尾草绿、奶茶棕、灰粉、炭灰”等低饱和预设色。

移除现有手工颜色、旅行场景和忌穿单品输入。提交条件为目的地、合法日期和至少一种风格；颜色允许不选。多选风格和颜色分别拼接为文本，继续传入现有 `style_preference` 与 `color_preference` 参数，不改变 workflow 接口。

### AI 计算页

保留现有真实调用和约 90 秒生成过程，不伪造 3 秒完成：

- 显示缓慢漂浮的半透明织物形状和柔和呼吸光晕。
- 真实 SSE 事件驱动进度文案逐步淡入。
- 请求失败显示简洁原因、重新生成和返回修改条件。
- 不修改 Worker、Coze workflow ID 或当前多日处理机制。

### 结果页

结果页继续在 plan 流程第三步呈现，避免创建重复路由：

- 顶部天气概览：横向日期卡片，显示天气图标、温度区间；天气源提供时补充紫外线和降水概率。
- 中部穿搭策略：显示按天气和地域总结的策略文字，以及 workflow 返回的真实旅行场景穿搭图。
- 下部搭配清单：上衣、下装、外套、鞋履、配饰。每项显示名称、推荐理由和参考图。由于当前 workflow 只返回整套穿搭图，本期各项复用同一场景图的不同裁切区域，不增加新的图片生成请求。
- 固定底部操作仅保留“下载图片”和“重新设计”。下载为主按钮，重新设计为辅助按钮。

“重新设计”清空当前结果并返回信息采集页，保留用户刚刚选择的条件以便调整。

## 数据流

1. 首页进入 plan 页面。
2. 城市选择页返回 `CityInfo` 并写入 Zustand 草稿。
3. 日期、风格数组和颜色数组写入草稿状态。
4. 提交时将多选值转换为 workflow 现有字符串参数。
5. `generateOutfitPlan` 继续通过 Cloudflare Worker 获取 Open-Meteo 天气并调用 Coze。
6. SSE 进度更新计算页；最终内容标准化为 `DailyOutfit[]`。
7. 结果只保存在当前内存状态，不写入 LocalStorage 或历史列表。
8. 下载操作将结果区域生成长图并调用浏览器下载；失败时显示明确提示。

## 视觉与动效

- 主色：鼠尾草绿、燕麦白、雾霾蓝、奶茶棕、灰粉。
- 背景：温暖米白，避免纯白大面积刺眼。
- 字体：系统圆润无衬线字体栈，正文宽松行高。
- 卡片：24–32px 大圆角、低透明阴影、无硬边框。
- 动效：400–900ms 淡入和位移，6–12 秒装饰漂浮；不使用快速闪烁、弹跳或高频循环。
- 触控：主要按钮高度不少于 52px，点击区域满足移动端操作。

## 错误与缺省状态

- 未完成必填项时禁用提交，并在对应分组旁显示温和提示。
- 城市搜索无结果时显示“暂无匹配城市”。
- 天气或 workflow 请求失败时保留当前选择，允许重试。
- 图片字段为空或不可访问时显示柔和缺省图，文字方案仍可查看。
- 下载失败时提示用户重试，不生成历史记录。

## 验收与测试

### 自动验证

- 首页只显示 slogan、主按钮和无动作历史入口。
- 主按钮进入信息采集页。
- 目的地返回后正确回显。
- 日期选择和 7 天限制正确。
- 风格、颜色支持多选和选中态。
- workflow 请求包含拼接后的风格与颜色参数。
- 计算页根据 SSE 事件渐进展示步骤。
- 结果页渲染天气、策略、图片和搭配清单。
- 重新设计返回采集页。
- 下载成功和失败路径均有反馈。
- 运行 TypeScript、单元测试和 H5 生产构建。

### 实际浏览器验收

按照用户提供的三组路径在移动端视口逐项操作：首页、信息采集页、计算页、结果页。填写一组真实数据调用已发布 workflow，等待结果并验证下载和重新设计。发现本期范围内问题时直接修复后重新验收。
