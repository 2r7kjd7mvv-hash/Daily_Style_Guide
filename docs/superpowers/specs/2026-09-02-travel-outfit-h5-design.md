# 旅行穿搭 H5 设计说明

## 目标

为 C 端旅行用户提供一套轻量、易操作的 H5 穿搭规划体验。用户选择目的地、旅行日期及个人偏好后，系统结合目的地天气、地域特征和 Coze AI 工作流，为旅行周期内的每一天生成可保存的穿搭策略与穿搭图片。

本期只交付 H5，不处理微信、抖音等小程序平台适配。

## 核心体验

底部导航包含“首页、穿搭、我的”。首页负责发现与发起设计；设计流程负责采集条件、展示生成过程和结果；穿搭页负责搜索与管理已保存方案；我的页面提供个人信息和常用入口。

首页顶部显示当前城市及定位图标，点击进入城市选择。首屏使用 3–4 张竖版旅行主题 Banner 轮播，第一张提供“设计我的穿搭”主操作。首页下方展示最近出行的重点穿搭及历史行程摘要。

设计流程分三步：

1. 选择目的地、开始和结束日期，并填写风格、颜色、场合和避雷单品。
2. 展示天气获取、地域分析、风格匹配和 AI 生成等流式进度。
3. 按日期展示图片、天气、体感、上衣、下装、外套、鞋履、配饰和提醒，底部固定“保存我的穿搭”和“重新设计”。

保存后方案进入穿搭页。穿搭页默认按出行开始时间倒序，最近出行详细展示当日穿搭，其他行程使用紧凑卡片。筛选支持目的地、出行时间和创建时间。

## 缺省与无数据状态

所有内容型页面使用统一的缺省图、标题、说明和操作按钮，避免只留下空白区域。缺省图采用轻量线性旅行插画，与海岸蓝绿色主题一致；标题统一使用“暂无数据”，说明文字与操作根据具体场景变化：

- 首页没有历史方案：提示“还没有旅行穿搭”，提供“设计我的穿搭”。
- 穿搭页没有任何方案：提示“还没有保存的穿搭”，提供“去设计穿搭”。
- 筛选没有匹配结果：提示“没有找到符合条件的穿搭”，提供“清除筛选”。
- AI 返回空结果：提示“这次没有生成有效方案”，提供“重新生成”和“返回修改条件”。
- 单日字段缺失：保留该日卡片，对缺失模块显示“暂无数据”，不隐藏整张卡片。
- 图片 URL 为空或加载失败：显示统一图片占位图和“图片暂未生成”，文字穿搭建议仍正常展示。

缺省组件应支持自定义插画类型、标题、说明、主操作和次操作，供各页面复用。

## 视觉方向

整体采用舒适、轻松、适合旅行场景的极简视觉。背景使用雾白，主色使用海岸蓝绿色，日光珊瑚色只用于关键行动和状态提示。卡片保留柔和圆角与轻阴影，减少无意义装饰。

标志性视觉是“旅行登机牌”日期条：在首页最近行程、生成结果和穿搭详情中统一承载日期、地点和天气，让跨页面信息关系直观一致。

建议基础色板：

- 海岸绿 `#247C6D`
- 浅海沫 `#DDF1EB`
- 雾白 `#F6F8F6`
- 墨色 `#172321`
- 岩灰 `#697673`
- 日光珊瑚 `#F28C6B`

## 前端架构

沿用现有 Taro 4、React、TypeScript、Sass Modules 和 Zustand 架构。页面位于 `src/pages/`，通用界面位于 `src/components/`，Coze 代理访问与数据转换集中在 `src/services/`，共享领域类型位于 `src/types/`。

页面不直接持有 Coze Token。H5 部署在 GitHub Pages 默认地址 `https://2r7kjd7mvv-hash.github.io/Daily_Style_Guide/`，并通过 Cloudflare Worker 调用 Coze。Worker 使用 Secret 保存 Token，前端只配置 Worker 的公开地址。未配置代理时，可回退到 mock 数据以保证本地演示流程；界面需清楚标识演示数据，避免误认为真实生成。配置了真实接口后，调用失败必须展示错误，不静默切换为演示数据。

## 外部接口

### 穿搭生成

前端向代理发送以下字段：

```json
{
  "workflow_id": "7680787686953058346",
  "parameters": {
    "city": "延边朝鲜族自治州",
    "province": "吉林省",
    "towns": "延吉市",
    "villages": "延吉",
    "start_time": "2026.9.2",
    "end_time": "2026.9.5",
    "style_preference": "韩国女团",
    "color_preference": "低饱和中性色",
    "avoid_items": "高跟鞋",
    "occasion": "城市漫步与拍照"
  }
}
```

Cloudflare Worker 负责保存 Coze Token、调用国内版流式端点并将事件转发给 H5。前端处理 `Message`、`Error`、`Interrupt`、`PING` 和 `Done` 事件，并通过事件 ID 检查流是否连续。Worker 只允许 GitHub Pages 正式域名和本地开发来源跨域访问。

最终 `Message.content` 为 JSON 字符串。解析层将 `date_list`、`image_url_list` 和 `output_list` 归一化为每日穿搭数组。`image_url_list` 中的每一项可能仍是 JSON 字符串，解析层需兼容直接 URL、JSON 字符串和对象三种形式。工作流返回可公开访问的临时图片 URL。MVP 不做 R2 转存；图片过期或加载失败后显示缺省图，文字方案继续保留。

### 定位

H5 使用浏览器 Geolocation API 获取经纬度。Cloudflare Worker 使用 OpenStreetMap Nominatim 完成国内外逆地理编码，设置明确的 `User-Agent`，并实施缓存和低频访问控制。用户拒绝授权、浏览器不支持或接口失败时，展示明确原因并保留手动选城入口。

## 状态与持久化

Zustand 保存当前草稿、访客用户和当前会话状态。MVP 不做真实登录，已保存穿搭通过现有服务边界写入浏览器本地存储，使刷新后仍能看到方案。清除浏览器数据、更换设备或使用无痕模式时不提供记录同步。

生成操作需防止重复提交。离开加载页时取消未完成请求或忽略过期事件。解析失败、网络失败、定位失败和图片加载失败均提供可恢复操作。

## 响应式与可访问性

页面以 375px 手机视口为主要设计基准，同时限制 H5 内容最大宽度，宽屏时居中显示。底部操作区适配安全区。交互控件提供清晰的焦点和禁用状态；动画遵循 `prefers-reduced-motion`；图片包含可理解的替代文本。

## 验证范围

- 运行 `npx tsc --noEmit`。
- 运行 `npm run build:h5`。
- 手动验证首页轮播与城市切换。
- 验证完整三步生成流程、流式进度、失败重试和重新设计。
- 验证结果图片和每日穿搭字段映射。
- 验证保存后进入穿搭页、筛选和排序。
- 验证定位授权、拒绝和手动选城路径。
- 验证首页无历史数据、穿搭列表为空、筛选无结果、AI 空结果及图片加载失败状态。
- 验证常见移动端宽度及桌面窄栏展示。
